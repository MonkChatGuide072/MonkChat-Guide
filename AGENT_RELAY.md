# Local Agent Relay

This relay lets Codex review and Google Antigravity implement a focused task in the same local MonkChat Guide repository. It is a local development tool only. It is not included in the deployed application and does not call a paid AI API from the website.

## Roles

- **Codex** is read-only. It creates the initial plan and reviews the Git diff and verification results.
- **Antigravity** is the only source-code writer during a relay run. It implements Codex's plan, runs focused checks, and responds to review feedback.
- **The relay** runs deterministic project checks and stops when Codex reports `PASS`, an agent reports a blocker, or the round limit is reached.
- **The Project Owner** remains the only approval authority for commit, push, pull request, merge, deployment, Supabase, Cloudflare, secrets, and production changes.

The agents run sequentially. They never edit the project concurrently.

## Permanent Safety Boundaries

The relay must never:

- run on `main` or `master`;
- commit, push, pull, merge, rebase, reset, stash, switch branches, or create tags;
- deploy or change Cloudflare Pages;
- run Supabase migrations or write to a hosted database, Auth, Storage, or Edge Functions;
- read, print, copy, edit, or create `.env` files or secrets;
- delete broad sets of files or use destructive Git commands;
- publish Buddhist or meditation content generated by AI;
- install dependencies, enable billing, or use a paid API;
- loop indefinitely.

The first version runs at most two implementation/review rounds by default. It always stops before commit or release.

## Prerequisites

1. Node.js and npm are installed.
2. Codex CLI is installed and signed in with the approved ChatGPT account.
3. Antigravity CLI is installed and signed in with the approved Google account.
4. Work starts on a dedicated feature branch created from the current `origin/main`.
5. The working tree is clean except for `.agent-sync/TASK.md`.
6. `npm ci` has already completed for the checkout.
7. Antigravity CLI uses its sandboxed permission preset so safe local edits can proceed without approving every command:

```json
{
  "toolPermission": "proceed-in-sandbox",
  "enableTerminalSandbox": true
}
```

Keep that setting in the Antigravity CLI user settings. Do not use an unrestricted or YOLO-style permission mode for this relay.

Check the commands from PowerShell:

```powershell
codex --version
agy --version
node --version
git status -sb
```

## Use

1. Edit `.agent-sync/TASK.md` and replace every template instruction with one focused task.
2. Preview what the relay will do. Dry-run is the default and does not invoke either agent:

```powershell
npm run agents:relay
```

3. Start the guarded two-round relay:

```powershell
npm run agents:relay -- --execute
```

The PowerShell wrapper is equivalent:

```powershell
.\scripts\agent-relay.ps1 -Execute
```

To use one round only:

```powershell
.\scripts\agent-relay.ps1 -Execute -MaxRounds 1
```

## Outputs

Each execution creates an ignored directory under `.agent-sync/runtime/` containing:

- the task snapshot;
- Codex's initial plan;
- Antigravity's report for each round;
- lint, test, and build logs;
- Codex's review for each round;
- `state.json` with the final status.

Possible final statuses:

- `ready_for_owner`: checks passed and Codex returned `PASS`;
- `revision_limit`: the task still needs work after the allowed rounds;
- `blocked`: a command, agent, or safety precondition failed.

None of these statuses means the work is deployed or approved. Review `git diff` and the runtime evidence before requesting owner approval.

## Recovery

- If a run is interrupted, inspect the newest runtime directory and `git status`.
- Do not use `git reset`, `git stash`, or checkout commands to clean up automatically.
- Start another run only after a human reviews the working tree. The relay removes its own lock after handled failures; remove a stale `.agent-sync/runtime/relay.lock` manually only after confirming no relay process is active.

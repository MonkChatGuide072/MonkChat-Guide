## การตรวจบนระบบจริง

| กรณี | วิธีตรวจ | ผล |
| --- | --- | --- |
| สมัครจาก origin ที่ไม่อนุญาต | HTTP ไป student-register | 403 |
| ส่งข้อมูลสมัครไม่ครบ | HTTP ไป student-register | 400 |
| ผู้สมัครส่ง auto_approve ทั้งที่ระบบรออนุมัติ | HTTP สมัครบัญชีทดสอบ | ได้บัญชี pending ไม่ข้ามนโยบาย |
| เข้าสู่ระบบด้วยบัญชี pending | Supabase Auth จริง | ล็อกอินได้ แต่เขียน progress ไม่ได้ |
| เปิดรับสมัครอัตโนมัติ | HTTP สมัครบัญชีทดสอบแยก | บัญชี active และล็อกอินได้ |
| Student อ่านข้อมูลฝึกตัวเอง | REST API ด้วย access token จริง | อ่านได้ |
| Student เปลี่ยนนโยบายผ่าน owner API | student-cohorts ด้วย token จริง | 403 |
| Student อ่านตารางนโยบายของ owner | REST API ด้วย token จริง | ไม่เห็นแถว |
| Owner เปลี่ยนนโยบาย | จำลอง JWT identity บนฐานข้อมูลจริงภายใต้ RLS ใน transaction | ผ่าน แล้ว rollback |
| Team member เปลี่ยนนโยบาย | จำลอง JWT identity บนฐานข้อมูลจริงภายใต้ RLS | ไม่ผ่าน |
| Active student เพิ่ม progress | RLS บนฐานข้อมูลจริงใน transaction | ผ่าน แล้ว rollback |
| บัญชีที่ระงับเขียน progress | REST API ด้วย token ที่มีอยู่จริง | ถูกปฏิเสธ |

การตรวจ owner แบบจำลอง identity ใน SQL ไม่ใช่การคลิก CMS ด้วยบัญชี owner จริง การใช้งานผ่านหน้าเว็บหลังล็อกอินควรตรวจอีกครั้งร่วมกับเจ้าของบัญชี ไม่ได้สร้างบัญชี owner หรือ team member เพิ่ม

## ข้อมูลทดสอบที่เหลือและสถานะสุดท้าย

- มีบัญชีนิสิตทดสอบ 2 บัญชี: `4011060` และ `4011059` แสดงชื่อ “ทดสอบระบบเท่านั้น — ไม่นับเป็นข้อมูลวิจัย” ทั้งสองบัญชีถูกตั้ง `is_active=false` เมื่อจบการตรวจ
- ไม่มี progress ของสองบัญชีทดสอบถูกเก็บค้าง: ตรวจได้ 0 แถว การทดสอบเขียนที่อนุญาตทำใน transaction แล้ว rollback
- นโยบายสุดท้ายคือ `auto_approve` ตรงโหมดเปิดรับเดิม
- ไม่แสดงหรือเก็บรหัสผ่านและ access token ลงเอกสารหรือ source รหัสผ่านทดสอบสุ่มในหน่วยความจำ การทดสอบบัญชีที่ active ลงชื่อออกเมื่อจบ
- ไม่มีการแก้บัญชีผู้ใช้จริง ไม่ลบข้อมูลเดิม และไม่เผยแพร่ frontend production ในรอบนี้
- Security advisor ไม่พบคำเตือนใหม่เกี่ยวกับตารางนโยบาย คำเตือน RPC และ password protection เดิมบันทึกไว้ในผลตรวจรับก่อนหน้า

## ผลต่อการทดลองและรายงาน

backend รองรับนโยบายรับสมัครชุดแก้แล้ว ใช้กับ frontend รุ่นที่ตรวจผ่านใน worktree ได้ ส่วนการตัดสินใจว่าจะเปิดเสียงเฉพาะช่วงเตรียมตัวหรือระหว่างกิจกรรมยังรอเจ้าของยืนยัน ไม่ถือว่าการ deploy backend เป็นการยืนยันขอบเขตเสียง

พรีวิวในเครื่องยังไม่มี `.env.local` สำหรับ Supabase และ backend ปฏิเสธ origin `http://127.0.0.1:4183` / `http://localhost:4183` ด้วย 403 ตาม CORS ที่ตั้งไว้ จึงยังเป็นโหมดสาธิต การตรวจบัญชีจริงรอบนี้ทำผ่าน HTTP/Auth API โดยตรงด้วย origin ของเว็บโครงการที่อนุญาตแล้ว ไม่ใช่ผลทดสอบคลิกหน้าล็อกอินในพรีวิว การตรวจ UI บัญชีจริงรอบถัดไปต้องใช้ frontend บน origin ที่อนุญาต หรือจัดสภาพแวดล้อมพรีวิวที่เชื่อมต่อให้ครบก่อน

บัญชีทดสอบสองบัญชีและรอบสาธิตซอฟต์แวร์ต้องไม่นับรวมเป็นจำนวนพระนิสิตที่เข้าร่วมการศึกษา ผลการตรวจ backend ยืนยันพฤติกรรมระบบ ไม่ใช่ผลเพิ่มความมั่นใจหรือประสิทธิผลการฝึก

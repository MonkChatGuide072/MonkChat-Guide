## สิ่งที่รวม

1. หน้าสมาธิ 4 ส่วนจาก Windows: คำแนะนำเริ่มต้น → เสียง → บทอ่าน → คำแนะนำประกอบ พร้อมเส้นทางกลับ `/visit`
2. ตัวอ่านคำบรรยายที่รองรับรูปแบบไฟล์ปัจจุบัน และเก็บไฟล์ VTT ร่าง/บันทึกผู้ตรวจไว้ครบ
3. FAQ ค้นหาได้และการ์ดบอทสาธารณะจากคำตอบรับรองแล้ว ไม่ส่งคำถามไปยัง AI; แหล่งอ้างอิง/ผู้ตรวจยังอยู่เฉพาะหน้าจัดการ
4. ผู้ช่วย AI ส่วนตัวสำหรับพระนิสิตที่ `/admin/assistant` ตามแผนปัจจุบัน ตรวจ token/active role ทางเซิร์ฟเวอร์ ระบุว่าเป็นร่าง และแจ้งเมื่อไม่มี Q&A ของโครงการรองรับ
5. หน้าฟอร์มแก้ Q&A คงข้อจำกัดจาก Windows รวมกับการตรวจแถวที่บันทึกได้จริงและการจัดการ lock จากฐานข้อมูล
6. migration ล็อก Q&A เหลือฉบับเดียว `20261025130443_lock_verified_qa_content.sql` เพิ่ม trigger ก่อนตัวปรับสถานะเดิมและล้างสถานะ/ผู้ตรวจเมื่อคืนเป็นร่าง ไม่มี migration พฤศจิกายนซ้ำในชุดใช้งาน
7. เอกสารขอบเขตรุ่นล่าสุดแยกประวัติ 25 ตุลาคมออกจากข้อยกเว้นผู้ช่วย AI ส่วนตัวในแผนส่งงานปัจจุบัน

## ข้อแก้ไขข้อสรุปก่อนหน้า

Decision 26 ใน Windows มีมติไม่ใช้ generative chatbot จริง สาขา AI ใน GitHub วันที่ 14 ตุลาคมเก่ากว่าเอกสารวันที่ 25 ตุลาคม จึงไม่ควรใช้สาขานั้นปฏิเสธประวัติมติดังกล่าว การเพิ่ม AI ส่วนตัวในชุดนี้อ้างอิงแผนที่ทบทวนและให้เริ่มในบทสนทนาปัจจุบัน ไม่ได้เปลี่ยนบอทสาธารณะให้ใช้ AI

## สื่อจริงที่ตรวจเพิ่ม

อ่าน metadata แทร็กที่เผยแพร่แล้ว 1 รายการ และดาวน์โหลดเสียง/คำบรรยายจาก Storage ด้วย public SDK policy:

- เสียง MP3 3,188,707 ไบต์: ffprobe ระบุ 326.191 วินาที และถอดรหัสจนจบด้วย ffmpeg ได้ 326.140 วินาที จึงยาวประมาณ **5:26** ไม่ใช่ 5:00 ตาม `duration_seconds=300` ในฐานข้อมูล
- VTT ไทย/อังกฤษโหลดได้ทั้งคู่ ตัวอ่านของชุดรวมอ่านได้ภาษาไทย 22 cues และอังกฤษ 22 cues; ทั้งคู่สิ้นสุดที่ 300 วินาที
- ยังมีช่วงท้ายเสียงประมาณ 26 วินาทีที่อยู่นอก timeline คำบรรยาย ต้องฟังเทียบก่อนตัด/ย้ายซับ ไม่ได้แก้เสียงหรือ Storage ในรอบนี้
- ฐานข้อมูลไม่ได้ระบุ `speaker_name` และ metadata ในไฟล์อ้างถึง Lp Pasura จึงยังยืนยันไม่ได้ว่าเป็นเสียงพระนิสิตตามโจทย์ ต้องยืนยันผู้บันทึก/สิทธิ์ใช้
- การโหลดและ parse สำเร็จไม่ได้ยืนยันความถูกต้องของคำถอดเสียง คำแปล หรือความตรงจังหวะทุก cue

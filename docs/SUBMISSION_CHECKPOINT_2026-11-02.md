อัปเดต 3 พฤศจิกายน 2569: เตรียม migration ล็อก Q&A รับรองแล้วและแก้หน้าฟอร์มเรียบร้อยในชุดทดสอบ ฐานข้อมูลจำลอง Q&A ผ่าน 20 checks และชุดแอปผ่าน 55 tests ดู `QA_VERIFIED_CONTENT_RELEASE.md` ก่อนติดตั้งจริง ยังต้องเทียบ migration จาก Windows และทดสอบบัญชีจริง

- สำรอง working tree เดิมใน `feature/monkchat-chatbot-live` ไว้ก่อนแก้ไข ไม่ reset, clean หรือทิ้งไฟล์เดิม
- สร้าง worktree แยก `prep/submission-20261102` จาก `main` ที่ `c934370`
- นำ AI สำหรับพระนิสิตจาก commit `dd4b717` ของ `feature/monk-ai-prototype` กลับมาใช้ ทั้งหน้า `/admin/assistant` และ Pages Function `/api/monk-assistant`
- รักษาหน้า Q&A สาธารณะที่อ่านคำตอบรับรองแล้ว ร่างแชตสาธารณะและข้อมูลยังไม่รับรองของ working tree เดิมไม่ได้ถูกรวมเข้ารอบนี้
- ตรวจ token และ active Owner/Team Member ทางเซิร์ฟเวอร์ก่อนอ่านข้อมูลหรือเรียก AI
- รับเฉพาะ JSON ขนาดจำกัด ปฏิเสธ payload ผิดรูปแบบและคำขอข้าม origin ตั้งเวลารอการอ่าน Supabase
- ระบุเมื่อไม่พบ Q&A รับรองแล้วที่ตรงกับคำถาม แยกข้อความเซสชันหมดอายุ/ไม่มีสิทธิ์/บริการไม่พร้อม
- ยกเลิกคำขอเมื่อเปลี่ยนภาษา/ผู้ใช้ ป้องกันคำตอบเก่าปะปน และจำกัดความยาวประวัติที่ส่งกลับไปในคำถามถัดไป
- คำตอบ AI ยังเป็นร่างสำหรับพระตรวจ และไม่มีขั้นตอนบันทึกหรือเผยแพร่เข้าคลัง Q&A อัตโนมัติ
- คืนข้อกำหนดและ Decision 26 จากสาขา AI ที่บันทึกข้อยืนยัน 14 ตุลาคม ไม่ใช้ข้อความในรายงานที่อ้างว่าได้ยกเลิก AI

## หลักฐานที่ตรวจจากระบบจริงแบบอ่านอย่างเดียว

### คลัง Q&A

พบ 4 รายการที่มี `verification_status=verified`, `content_status=published` และ `is_published=true` แต่ละรายการมีคำแปลไทยและอังกฤษ:

1. ทำไมชาวพุทธจึงนั่งสมาธิ?
2. ใครคือชาวพุทธที่แท้จริง?
3. ถ้าใจฟุ้งซ่านขณะนั่งสมาธิควรทำอย่างไร?
4. ศาสนาพุทธคืออะไร?

นี่เป็นสถานะที่บันทึกในฐานข้อมูล ไม่ใช่การรับรองเนื้อหาใหม่โดยผู้พัฒนา ร่าง 15 ข้อต้องให้ผู้ตรวจเนื้อหารับรองแยกก่อนนำไปเผยแพร่

### Cloudflare

- Pages project `monkchat-guide` ใช้ `main` เป็น production branch
- Preview ล่าสุดที่ตรวจพบเป็น deployment ของ `dd4b717` เมื่อ 14 ตุลาคม มีสถานะสำเร็จ
- ไม่พบ AI binding ใน deployment configuration ที่ API คืนมา ต้องจัดเตรียม binding ชื่อ `AI` บน Preview แล้ว redeploy ก่อนทดสอบผ่านเว็บจริง
- มีตัวแปรชื่อ `VITE_SUPABASE_URL` และ `VITE_SUPABASE_PUBLISHABLE_KEY` อยู่แล้ว โค้ดรองรับชื่อเหล่านี้ จึงไม่ต้องคัดลอกรหัสลับลง repository
- การอ่านแผนผ่าน subscriptions API ถูกปฏิเสธด้วยข้อจำกัด OAuth จึงยังยืนยัน Workers Free จาก API นี้ไม่ได้ ไม่ได้เปลี่ยนแพ็กเกจหรือเรียก inference ที่อาจมีค่าใช้จ่าย

### ช่องว่างสิทธิ์ Q&A — P0 ก่อนเผยแพร่

ฐานข้อมูลจริงอนุญาต active Team Member ให้อัปเดต `qa_translations` ได้ ส่วน trigger ของ `qa_items` รักษาสถานะรับรอง/ผู้รับรองไว้ แต่ไม่ล็อกข้อความในตารางคำแปล ไม่พบ trigger ล็อกข้อความรับรองแล้วบน `qa_translations` ในผลตรวจ

จึงมีช่องทางที่เนื้อหาเปลี่ยนได้โดยยังคงสถานะรับรองเดิม ต้องเทียบ migration `lock_verified_qa_content` ที่รายงานว่ามีใน Windows กับ schema จริง และทดสอบทั้งการอนุญาตและการปฏิเสธก่อนติดตั้ง ไม่ได้เขียนทดสอบลงฐานข้อมูลจริงหรือแก้ RLS ในรอบนี้

## สิ่งที่ยังไม่พิสูจน์

ผลตรวจโค้ดรอบนี้: 51 tests ผ่านใน 8 ไฟล์, lint ผ่าน, TypeScript/production build ผ่าน และ `git diff --check` ผ่าน การเทียบไฟล์ใน checkout เดิมกับ archive ไม่พบไฟล์เปลี่ยนแปลง

- ไม่มี live authenticated AI round trip ในรอบนี้ ผลโมเดลในการทดสอบเป็น mock
- ยังไม่มีการสาธิต CMS Login → แก้ → บันทึก → ตรวจ → เผยแพร่ ด้วยบัญชีจริง
- ยังไม่ยืนยันการแสดงผล 360/390/768/1024/1440px: ไม่มี Chromium ใน runtime และการดาวน์โหลดไม่สำเร็จ; Cloud Browser เปิด local dev server ไม่ได้ (`ERR_CONNECTION_REFUSED`)
- ยังไม่ได้เทียบไฟล์ล่าสุดในเครื่อง Windows โดยเฉพาะหน้าสมาธิใหม่และ migration ที่รายงานไว้ ห้ามนำชุดนี้ไปทับทั้งโฟลเดอร์ Windows
- ยังไม่ได้ยืนยันผู้บันทึกเสียง 5 นาทีและตรวจเสียง/VTT ตามเวลาในรอบนี้
- ไม่มี commit, push, merge, deployment, การสร้างบัญชี หรือการเปลี่ยนข้อมูลจริงในรอบนี้

## คิวก่อนส่งที่คงไว้

1. เทียบงาน Windows กับชุดเตรียมส่ง โดยเก็บเฉพาะไฟล์ที่เกี่ยวข้องและตรวจ conflict
2. ตั้งค่า Workers AI เฉพาะ Preview บน Workers Free, redeploy และถามจริง TH/EN ด้วยบัญชีทีม
3. ปิดช่องว่างการแก้เนื้อหา Q&A รับรองแล้ว พร้อมทดสอบ Owner/Team/Public
4. ตรวจเนื้อหาจากชุดร่าง 15 ข้อ รวมถึง CMS, เสียง, คำบรรยาย และ QR → `/visit`
5. แก้ความอ่านง่าย/สถานที่/การนำทางเฉพาะจุด แล้วเผยแพร่เวอร์ชันที่ตรวจผ่าน
6. ปรับสไลด์เดิม 13 หน้าและหลักฐานสาธิตให้ตรงกับของจริง

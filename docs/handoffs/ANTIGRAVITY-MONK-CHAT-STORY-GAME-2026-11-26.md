## 1. เป้าหมายที่เจ้าของต้องการ

เพิ่มส่วนใหม่ให้พระนิสิตฝึกดำเนินบทสนทนาในบริบท Monk Chat ผ่านเรื่องราวต่อเนื่อง เลือกคำพูดหรือการกระทำ แล้วผู้มาเยือนตอบกลับและเหตุการณ์เปลี่ยนไปตามสิ่งที่เลือก ไม่ใช่เพียงข้อสอบ A/B/C/D ที่เปลี่ยนโจทย์โดยไม่มีเรื่องราวเชื่อมกัน

เจ้าของขอให้โครงร่างเสร็จวันนี้เพื่อส่งต่อได้ รุ่นแรกทำเพียงฉากภาพนิ่ง/ภาพร่าง + บทสนทนา + ทางเลือก + ฉากถัดไปก่อน การเดิน ตัวละครเคลื่อนไหว เสียงพากย์ และ animation เป็นการพัฒนาทีหลัง

**ส่วนใหม่นี้แยกจากแฟลชการ์ด การ์ดคำศัพท์ เครื่องมือเสียง เกมข้อสอบเดิม และบทฝึกที่มีอยู่ ไม่แทนที่หรือรื้อส่วนเดิม** คงธีมและการ์ดของเว็บเดิมด้วย

## 2. Monk Chat ในบริบทที่เจ้าของอธิบาย

ข้อมูลต่อไปนี้มาจากคำอธิบายกิจกรรมของเจ้าของ ใช้เป็นบริบทออกแบบ ไม่ใช่ข้ออ้างว่างาน Monk Chat ทุกแห่งมีขั้นตอนเดียวกัน

- พระนิสิตไปทำกิจกรรมที่วัด พบผู้มาเยือนชาวต่างชาติ ชวนเข้าร่วมโดยให้เขาตัดสินใจได้
- เมื่อผู้มาเยือนนั่งร่วมกิจกรรม พระนิสิตต้อนรับ ชวนทำความรู้จัก เช่น มาจากไหน เคยร่วม Monk Chat หรือฝึกสมาธิหรือไม่ และถามความสนใจของเขา
- มีการสนทนาถาม–ตอบเรื่องพระพุทธศาสนา ชีวิตพระ หรือสิ่งที่เขาเห็น เช่น จีวร การโกนผม บทบาทของพระ
- ชวนร่วมฝึกสมาธิ อธิบายและเตรียมตัว นำปฏิบัติตามเนื้อหาที่โครงการตรวจแล้ว
- หลังฝึก ชวนเล่าประสบการณ์อย่างเปิดกว้าง เช่น รู้สึกอย่างไร มีอะไรอยากถาม ไม่ตั้งสมมติฐานว่าทุกคนต้องเห็นดวงแก้วหรือสงบเหมือนกัน
- หลังสนทนา อาจชวนถ่ายภาพหมู่ ขอความยินยอม จัดตำแหน่งให้เหมาะสมกับข้อปฏิบัติของโครงการ และกล่าวลา
- เกิดเหตุการณ์แทรกได้ เช่น ผู้มาเยือนมีเวลาน้อย ปฏิเสธ ไม่เข้าใจสำเนียง ขอถ่ายรูป ไม่อยากร่วมสมาธิ หรือเข้ามาใกล้ระหว่างจัดภาพ

นี่คือกิจกรรมพบปะจริงที่พระนิสิตเป็นเจ้าบ้านและผู้สนทนา ไม่ใช่ตัวละครนักบวชในโลกแฟนตาซี เป้าหมายคือสื่อสารให้เข้าใจ รักษาความสุภาพและข้อปฏิบัติ และไม่กดดันผู้มาเยือน

## 3. ขอบเขตและความเป็นจริงของเรื่อง

สถานที่ฉากหลักใช้บรรยากาศกิจกรรม Monk Chat อยุธยา ณ วัดมหาธาตุตามเว็บโครงการ: พื้นที่นั่งพูดคุย ลาน/จุดนัดพบที่มีผู้มาเยือน จุดนั่งฝึก และพื้นที่ถ่ายภาพ ไม่สร้างตำแหน่งโบราณสถานจริงหรือข้ออนุญาตเฉพาะขึ้นเองจากจินตนาการ

- ตัวละครและบทพูดในชุดตัวอย่างเป็นเรื่องสมมติเพื่อฝึก ไม่ใช่ข้อมูลวิจัยหรือคำพูดผู้ร่วมกิจกรรมจริง
- แสดงบริบทให้เห็นเสมอ: อยู่ช่วงไหนของกิจกรรม ผู้มาเยือนเพิ่งพูดอะไร และเป้าหมายของฉากคืออะไร
- ถ้าต้องใส่เวลา สถานที่จัดจริง ค่าใช้จ่าย หรือเงื่อนไขร่วมโครงการ ให้ใช้ข้อมูลปัจจุบันที่ตรวจแล้วจากเว็บ/CMS ห้ามแต่งเอง
- คู่สนทนามีความต้องการและข้อจำกัดต่างกัน เช่น เวลา ภาษา ความสนใจ ไม่กำหนดพฤติกรรมตามสัญชาติ เพศ หรืออายุแบบเหมารวม
- ฉากบุคคลเข้ามาใกล้ ใช้ทักษะขอเว้นระยะอย่างสุภาพและการจัดภาพที่เหมาะสม ข้อความเกี่ยวกับพระวินัยเฉพาะต้องให้พระผู้รับผิดชอบตรวจ ไม่ให้ระบบตัดสินผู้หญิงว่าเป็นเหตุการณ์ผิดหรือเป็นภัยโดยตัวมันเอง

## 5. วิธีทำให้เป็นเกมสนทนาที่เรียนรู้ได้

1. แสดงภาพฉาก + ประโยคที่คู่สนทนาพูดภาษาอังกฤษ + คำแปลไทยที่เปิดดูได้
2. ให้เลือก2–3ประโยค/การกระทำที่ต่างกันจริง ไม่ใช้ตัวลวงไร้เหตุผลทุกข้อ
3. หลังเลือก ให้เห็นปฏิกิริยาหรือประโยคถัดไปของผู้มาเยือนก่อน แล้วจึงมีคำอธิบายสั้นว่าตัวเลือกนี้ช่วย/ติดขัดอย่างไร
4. บางฉากมีคำตอบเหมาะสมได้มากกว่าหนึ่งแบบ เช่น คำชวนแบบสั้นหรือแบบสุภาพเต็มประโยค
5. ถ้าเขาไม่เข้าใจ ให้มีทางพูดใหม่ ถ้าผู้เรียนเลือกคำพูดกดดัน ให้เห็นผลว่าอีกฝ่ายอึดอัดและมีทางแก้ ไม่แค่ขึ้นเครื่องหมายผิดแล้วข้ามข้อ
6. จบฉากแล้วทบทวนประโยคที่เลือก จุดที่ควรปรับ และเส้นทางที่ยังไม่ได้ลอง
7. ให้ลองใหม่จากฉากที่ติดได้ ไม่บังคับเริ่มเรื่องใหม่ทั้งหมด

สิ่งที่วัดในรุ่นแรกคือการเลือกคำพูดตามเป้าหมายฉาก ไม่อ้างว่าผ่านเกมแล้วพูดคล่องหรือพร้อมปฏิบัติหน้าที่จริง100% การกดอ่านครบ ความคืบหน้า และความถูกต้องของคำตอบต้องแยกกัน

## 6. โครงหน้าจอรุ่นแรก

- เมนูใหม่ชื่อเสนอ: “สถานการณ์ Monk Chat / Monk Chat Stories” แยกจากเมนูฝึกเดิม
- หน้ารวมบท: ชื่อบท เป้าหมายสั้น ๆ และปุ่มเริ่ม ไม่มีคะแนนพร้อมใช้งานที่สร้างขึ้นเอง
- หน้าเล่น: แถบชื่อบท → ภาพฉากหลัก → ผู้พูดและบทสนทนา → ทางเลือก → ปฏิกิริยา/feedback → ปุ่มไปต่อ
- ให้มีปุ่มเปิดคำแปลไทย ทบทวนประโยค และออกจากบท พร้อมป้องกันผลหายโดยไม่บอก
- มุมมองรุ่นแรก: พระนิสิตเป็นผู้เล่นมุมมองบุคคลที่หนึ่ง เห็นผู้มาเยือนและฉากตรงหน้า ใช้ภาพนิ่งก่อน ไม่ต้องทำ3Dหรือระบบเดิน
- คงหน้าอ่านง่ายมือถือและใช้ธีม navy/cream/gold ตามเว็บจริง ไม่เปลี่ยนงานเดิมเป็นหน้าตาเกมทั้งเว็บ
- ความคืบหน้ารุ่นแรกอยู่ในรอบที่กำลังเล่นก่อน ถ้าจะเก็บข้ามรอบต้องระบุ local/account ให้ตรงจริง ไม่อ้างว่าเก็บ cloud แล้ว

## 7. ตัวอย่างเรื่องเดียวที่ทำให้เล่นจบได้ก่อน

ไฟล์ `monk-chat-story-sample-2026-11-26.json` ที่อยู่ข้างเอกสารนี้ให้โครงฉาก บทสนทนาสองภาษา ทางเลือก feedback และ next node พร้อมฉากจบ ใช้ตรวจโครงสร้างและทำต้นแบบ ไม่ใช่เนื้อหาผ่านผู้เชี่ยวชาญแล้ว

โครงเรื่อง: พบผู้มาเยือน → ชวนร่วม → ต้อนรับ → ทำความรู้จัก → คำถามเกี่ยวกับพระ → ชวนสมาธิ → เตรียมตัว → หลังนั่ง → ชวนถ่ายภาพ → จัดระยะ → กล่าวลา

มีทางแยกให้ปฏิเสธกิจกรรมอย่างสุภาพ สนทนาแทนสมาธิ ขอให้พูดง่ายขึ้น ขอทบทวนเมื่อไม่แน่ใจ และไม่ถ่ายภาพ สถานการณ์ทั้งหมดมีเส้นทางไปฉากจบ ไม่ทำทางเลือกที่ลิงก์เสีย

ลำดับฉากในเกมไม่ใช่เครื่องเล่นเสียงสมาธิสาธารณะ ไม่เรียก Timer ดวงแก้วที่กำลังส่งต่ออีกงานหนึ่ง และไม่เปิดเสียงจริง/เปลี่ยนหน้าอื่นโดยไม่กด

## 10. ขั้นส่งงานเป็นช่วง

**ช่วงแรก — โครงและต้นแบบหนึ่งเรื่อง:** อ่านบริบทนี้ ตรวจเนื้อหาและคำแปล เลือกภาพเดิมหรือภาพร่าง ใส่graph แสดงทางเลือก → ผลตอบกลับ → ฉากถัดไป เล่นจบทั้งเส้นทางหลักและทางปฏิเสธได้

**ช่วงถัดไป — เพิ่มบทและทบทวน:** เพิ่มบทตามตาราง ปรับfeedbackให้ตรงเป้าหมาย และพิจารณาแบบทดสอบท้ายบทเมื่อเนื้อหาพร้อม

**ภายหลัง — ภาพเคลื่อนไหวและเสียง:** เติมการเดิน/ท่าทาง/ภาพ/เสียงพากย์โดยรักษาgraphเดิม ไม่ต้องทำก่อนต้นแบบเล่นจบ

ไม่ทำrankingหรือขยายเป็นเกมโลกเปิด ไม่เปลี่ยนระบบฝึกเก่าทั้งชุด และไม่แก้ภาคนิพนธ์หรือฟอร์มวิจัยในรอบนี้ เว็บกับเล่มมีความสอดคล้องที่จัดไว้แล้ว ให้บันทึกส่วนใหม่เป็นงานต่อยอดตามสถานะจริง

## 11. ตรวจรับงาน

- ทุกchoiceชี้ไปnodeที่มีจริง ทุกnodeที่เล่นได้มีทางไปฉากจบ และไม่มีการบังคับเลือกคำตอบที่ไม่สุภาพเพื่อเดินต่อ
- เลือกต่างกันต้องเห็นผลตอบกลับหรือทางไปต่อที่ต่างกันอย่างมีความหมาย มีทางแก้เมื่อสื่อสารพลาด
- มีเส้นทางปฏิเสธคำเชิญ/ปฏิเสธสมาธิ/ปฏิเสธภาพที่จบอย่างเหมาะสม ไม่หักคะแนนเพราะเคารพการปฏิเสธ
- คำถามหลังนั่งไม่บังคับว่าต้องเห็นแสง/ดวงแก้ว/รู้สึกสงบ และไม่ใช้ประสบการณ์สมาธิเป็นคะแนน
- เนื้อหาพระวินัยและคำอธิบายธรรมะตรวจโดยผู้รับผิดชอบก่อนเผยแพร่จริง ต้นแบบใช้สถานะdraftและแยกจากpublic content
- ไทยเป็นUIหลัก อังกฤษเป็นบทสนทนาที่ใช้ฝึก มีคำแปลช่วย และใช้งานด้วยkeyboardได้
- ตรวจมือถือ360/390px และ768/1024/1440px ไม่ล้นจอ
- ผ่านlint/type/tests/build/diff-check พร้อมทดสอบการสลับบัญชีไม่ให้ความคืบหน้าปะปนถ้ามีการเก็บผล
- ไม่เปลี่ยนแฟลชการ์ด/บทเรียน/ข้อสอบเดิม ไม่ทำให้หลังบ้านที่เพิ่งเผยแพร่เสีย
